2. Scope — what the system does today

Windows-only background application. It samples window focus and idle state, captures a screen frame on triggers, sends it to a local vision model (Ollama, qwen3-vl:2b), stores the results in SQLite, and exposes a CLI that renders human and LLM-oriented reports.

Win32 sensorsForeground window, process, title, idle time
CaptureGDI screen grab, one JPEG at quality 75
OllamaStructured JSON label per frame
SQLiteEvents and insights, ISO-8601 UTC text
CLISchema v2.0 JSON and 3.0-llm narrative reports
  • Four .NET projects: Service (host loop), Core (sensors, capture, inference, queue, storage), Common (models, settings), CLI (2,413 lines, Spectre.Console).
  • Service runs as a console process or a Windows service with --service; autostart via a shell:startup shortcut.
  • Sampling every SamplingIntervalSeconds (default 5 s); one database row per tick while idle (about 720 rows per hour).
  • Capture triggers: periodic every 3 minutes (hardcoded), focus change and idle resume throttled to once per 10 seconds (hardcoded).
  • Frame count is min(MaxFramesPerCapture, MaxDurationSeconds x FrameRate); the shipped configuration yields exactly one frame.
  • Inference posts to /api/chat with stream:false, think:false, a JSON-schema format, temperature 0.1, top_p 0.9, num_predict 1024, and only the middle frame as base64. HTTP timeout is infinite; health check is GET /api/tags.
  • Queue: four priority levels (Low to Critical), unbounded channels with a manual capacity counter, four concurrent workers, drop when full.
  • Storage: new SQLite connection per operation; timestamps written as DateTime.UtcNow.ToString("O") text; date filtering relies on lexical BETWEEN.
  • CLI resolves the database at ./Data/ActivityData.db, then %ProgramData%\ActivityMonitor\Data\ActivityData.db.
  • Deployment is a copied publish/ folder plus a startup shortcut; logs are hardcoded to C:\ActivityMonitor\publish\Logs\.

3. Audit findings — checklist

Each defect is fixed during the port and recorded in release notes. Parity applies everywhere else.

  • BugFixed Phase 1Timezone comparison breaks on non-UTC machines. timeline and query bind local-offset strings into BETWEEN against Z-suffixed UTC timestamps; ranges are silently wrong. Fix: convert local dates to UTC in every command (done in query/stats/timeline/detailed/summary via jiff system-tz conversion).
  • BugCompaction never runs. CompactOldEventsAsync() has no callers, so events are never purged. appsettings.json also contains a typo key, "MaxEventAgeD ays", which is silently ignored. Fix: daily compaction job; serde alias for the legacy key.
  • BugHung inference freezes a worker. HttpClient.Timeout is infinite and ProcessingTimeoutSeconds is never read. Fix: real configurable timeout, default 120 s.
  • BugIdle time wraps after roughly 49.7 days of uptime. 32-bit tick arithmetic. Fix: GetTickCount64.
  • DocsREADME describes Windows.Graphics.Capture; the code uses GDI. Consent UI and capture border are documented but absent; multi-monitor and HiDPI are unsupported. Decision: port GDI exactly; WGC is a follow-up ticket.
  • DocsREADME is stale elsewhere. It lists files that do not exist, claims a .NET 9 build with a .NET 8 runtime, and advertises dotnet test although no test projects exist. Fix: rewrite README and SETUP in Phase 10.
  • DeadDead configuration. HighPriorityThreshold, RetainFrames and CompactionIntervalHours are never read. Decision: drop them; keep ProcessingTimeoutSeconds and implement it.
  • PerfPriority queue race. Unbounded channels plus an Interlocked counter; Clear() leaves semaphore permits behind. Fix: bounded tokio::sync::mpsc per priority level.
  • PerfHardcoded log path. Fix: logs under the executable directory or a configuration key.
  • PerfConnection churn. A new SQLite connection per operation, default journal mode. Fix: one guarded connection; optional WAL after a compatibility check.

5. Advantages of the Rust version

  • Single static executable of roughly 4 to 8 MB; no .NET runtime, no redistributable, no administrator rights. The current self-contained publish is around 70 MB.
  • Idle memory target below 20 MB against a current claim of about 50 MB; no garbage collector or JIT.
  • Explicit error handling. Result at every database, HTTP and FFI boundary removes the current catch-and-return-null class of silent data loss.
  • Genuine backpressure through bounded priority channels.
  • Zero data migration: same schema, same text timestamps.
  • Fast deployment and rollback: replace one executable, keep the .NET build as fallback.

6. Porting contract

  • SQL ports verbatim into rusqlite. Joins and limits stay in SQL.
  • Timestamps: %Y-%m-%dT%H:%M:%S.%7fZ. jiff's %7f truncates to exactly seven digits, matching .NET's 100 ns ticks. Never use jiff's default Display, which trims zeros. Unit tests pin known vectors including zero fractions.
  • JSON field order follows the C# declaration order, so outputs can be diffed textually.
  • Duration totals truncate, never round.
  • Null values are omitted; empty lists serialize as [], as in .NET.
  • Exit codes: 0 on success, 1 on handled failure or missing database.
  • Configuration: keep the appsettings shape and tolerate unknown keys.

8. Verification checklist

  • Golden differential tests. Generate a synthetic seed database; run the .NET CLI and the Rust CLI over it and compare canonical jq output for report, report --llm, stats, query, timeline, detailed and summary. Never use real screen data.
  • Unit tests for duration formatting, truncation, key normalization, segment accumulation, insight matching, project regex, timestamp formatting and drop policy.
  • Database compatibility in both directions. Rust reads a .NET-written database; .NET reads a Rust-written database; .schema output is identical.
  • Live service test. Manual focus changes; Ollama down produces a logged error rather than silence; Ollama up produces an insight row; stop drains cleanly.
  • Capture sanity. Capture the same screen with both stacks; compare decoded pixels and size band, never encoded bytes.

9. Deployment and rollback

  • No database migration; the existing file is used as-is.
  • Path resolution unchanged for the service and the CLI.
  • publish2/ holds two executables, appsettings and the data directory; logs live under the executable directory.
  • Startup shortcut is re-pointed to the new service executable after sign-off.
  • Rollback re-points the shortcut to the .NET build; no data conversion is needed either way.
  • After the soak period: remove the .NET projects, rewrite the cleanup script, delete NuGet remnants and the isolated SDK.

10. Risks and watch-outs

  • ClosedToolchains. Rust, MSVC build tools and an isolated .NET SDK are installed and verified.
  • OpenTerminal fidelity. Spectre.Console tables, panels and charts will not match exactly. JSON outputs are the contract; cosmetic drift is accepted.
  • OpenDate formatting. Narrative and date templates must be checked individually against C# output; the golden tests catch drift.
  • OpenJPEG bytes differ. Verify size band and visual quality only.
  • OpenService control parity. Start, stop, service name and event-log behavior need a real sc.exe-style test.
  • OpenLatency expectations. Inference remains seconds-scale; Rust improves memory and CPU, not GPU time.

11. Explicit non-goals

  • Windows.Graphics.Capture and multi-monitor support (follow-up).
  • Database encryption (a stated wish in SETUP.md, deferred).
  • SQLite WAL mode.
  • Installer and auto-update.
  • Cross-platform support.
  • Tests inside the .NET codebase; they retire with the C# implementation.

HTTP — 200 discover+tools/call, 202 notification, 406, 400 (-32022), 405 on GET, stdout byte-empty. deploy.ps1 ships the exe to publish2; SETUP.md documents the client mcpServers snippet.

  • Protocol core (hand-rolled, no SDK dep): JSON-RPC 2.0 loop over stdin/stdout. Modern era: every request carries _meta["io.modelcontextprotocol/protocolVersion"]; unknown version → error -32022 with supported: ["2026-07-28","2025-11-25","2025-06-18"]; results carry resultType: "complete"; server/discover MUST be implemented (returns supportedVersions, capabilities, _meta serverInfo, instructions). Legacy era: answer initialize / notifications/initialized / ping and legacy-shaped tools/list / tools/call. Handle notifications/cancelled (abort in-flight tool call).
  • Tools (all read-only, annotations.readOnlyHint: true, deterministic order, JSON Schema 2020-12 input/output schemas, results return both a text block with serialized JSON and structuredContent):
    • todays_timeline (optional date) — events + AI labels for a day, same join as CLI timeline.
    • session_summary (date, optional app) — per-app usage time + AI activity labels, like CLI summary.
    • activity_at (timestamp, optional windowMinutes) — what was on screen around a moment.
    • daily_report (date) — reuses the core report v2.0 JSON builder read-only.
    • ask_about_my_day (question, optional date) — builds a compact day context from the DB and answers via the existing OllamaClient (text chat, no images); degrades to "Ollama unavailable" error result, never blocks monitoring.
  • DB access: open SQLite read-only (mode=ro URI) so the running service's writes are never blocked; path resolution same as the CLI (./Data/ActivityData.db then %ProgramData%), overridable via --db / ACTIVITY_MONITOR_DB. Config from the same appsettings.json next to the exe for the Ollama endpoint/model.
  • Deps: only activity-monitor-core + serde/serde_json + jiff + tokio + tracing (+ rusqlite as dev-dependency for tests). Deferred (not in v1): resources, prompts, subscriptions/listen, tasks extension, MRTR.
  • Gates: unit tests driving the JSON-RPC loop in-process (server/discover, legacy initialize, tools/list, tools/call against a temp seeded DB, unknown-version error, cancelled notification); a live smoke against a real client config snippet (Claude Desktop / VS Code mcpServers JSON) documented in SETUP.md.
